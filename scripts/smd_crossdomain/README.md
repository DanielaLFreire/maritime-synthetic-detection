# SMD cross-domain generalisation

This sub-pipeline builds an independent maritime evaluation set from the
**Singapore Maritime Dataset (SMD)** and runs a **zero-shot cross-domain probe**
of every experimental arm on it. No model is trained or tuned on SMD: the
checkpoints evaluated here are exactly the CITRA-3D-Real models from the main
experiments, applied without any adaptation.

It produces the results reported in the paper's *"Zero-shot cross-domain
generalisation"* section (cross-domain results table). The probe corroborates
the two central directional effects on an independent domain (different waters,
different camera): naive public pre-training degrades performance relative to
the COCO baseline, while domain-adapted synthetic composition improves it.

## Why a dedicated preparation step

The SMD repackaging on Roboflow Universe ships with a **per-frame** train/val/test
split, which scatters every source video across all splits and would inflate any
metric. It also mixes on-board (moving-platform) and near-infrared footage with
the visible on-shore footage that is comparable to CITRA-3D-Real. The preparation
script therefore:

1. keeps **only visible on-shore** footage (drops `*_OB_*` on-board and `*NIR*`);
2. remaps the 9 original classes to a single `vessel` class
   (Boat, Ferry, Kayak, Sail boat, Speed boat, Vessel-ship; discards Buoy,
   Flying bird-plane, Other);
3. **re-splits by video** so no source video appears in more than one split;
4. **temporally subsamples** frames per video to reduce near-duplicates.

pip install roboflow ultralytics numpy

## Scripts and run order

```bash
# 1) Download + prepare the cross-domain eval set (all videos routed to test/)
python 01_prepare.py --out ./data/smd_clean

# 2) Verify integrity: modality breakdown + video-level leakage (should be 0)
python 02_check_integrity.py --root ./data/smd_clean

# 3) Zero-shot evaluation of all arms; writes the per-seed JSON
python 03_eval_crossdomain.py \
    --runs /path/to/runs \
    --data ./data/smd_clean/data.yaml \
    --out ../../results/smd_crossdomain.json
```

`02_check_integrity.py` can also be run on the raw Roboflow download
(`--root ./data/Singapore-maritime-5`) to confirm the original per-frame leakage.

## Reproducibility parameters

The evaluation set is fully determined by the constants below (defaults in
`01_prepare.py`). Changing them changes the set.

| Parameter | Value | Meaning |
|---|---|---|
| Roboflow project | `maritime-cumkb/singapore-maritime` v5 | source dataset |
| Keep rule | drop `_OB` and `NIR` | visible on-shore only |
| `VESSEL_IDS` | {0, 2, 4, 6, 7, 8} | classes merged into `vessel` |
| `--stride` | 4 | keep 1 of every N frames per video |
| `--ratio` | 0 0 1 | all videos to `test/` (zero-shot probe) |
| `--seed` | 42 | video shuffle seed |

With these defaults the set is **914 images from 36 distinct videos**, leakage-free.

Evaluation in `03_eval_crossdomain.py` uses `imgsz=640`, `conf=0.001`, `iou=0.7`
(consistent with the in-domain protocol). The arm → checkpoint mapping matches
this repository's run layout; for the sequential arms (A, B, A' frozen) the
**fine-tune** checkpoint is used, never the pre-train one.

## Outputs

- `data/smd_clean/` — the prepared dataset (**not committed**; regenerated by
  `01_prepare.py`). Add `data/Singapore-maritime-5/` and `data/smd_clean/` to
  `.gitignore`.
- `results/smd_crossdomain.json` — per-seed mAP50 / mAP50-95 for each arm
  (**committed**; backs the cross-domain results table).
